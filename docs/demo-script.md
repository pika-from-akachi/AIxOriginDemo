# 演示脚本与验收对照 (Demo Script / Definition of Done)

固件默认角色为**哨兵/触发端 Node_A**。用它完成 PRD 验收里
“第一个检测节点”的核心链路。

## 验收标准 (Definition of Done) 对照

| PRD 验收 | 在本 Demo 中如何验证 | 对应机制 |
|---|---|---|
| ① 两块 ESP32-S3 无路由器、按键触发 50ms 内状态同步 | 板A 短按切到“危险”，板B ≤1 帧(约80ms UI刷新)内进入紧急界面 | 状态变更**立即** ESP-NOW 广播(非周期等待)，UI 节流 80ms |
| ② OLED 按收到的风险等级实时刷新，无明显卡顿/乱码 | 切换时整屏同步更新；全 ASCII 字库+自绘大数字，无中文字库乱码问题 | `renderUi()` 节流 80ms、全缓冲刷新、4 线 SPI |
| ③ 完整叙事闭环：上游异常→节点广播→终端接收→屏幕输出逃生策略 | 短按模拟“上游泥石流”→广播→对端屏幕 `DANGER`+闪烁+逃生导航（`> SHELTER N`+剩余距离） | 全链路见下 |

> 关于“50ms”：ESP-NOW 空中时延本身在毫秒级；界面刷新以 80ms 为帧间隔，
> 如需肉眼更强的“即时感”，可把 `renderUi()` 里 `>= 80` 调小到 `40`。

## 场景叙事（评委视角）

> **场景**：山区暴雨。上游安置的哨兵节点感知到泥石流前兆 →
> 离网自组网把“危险”广播给下游节点 → 屏幕紧急显示撤离方向。

对应操作就是：**Node_A 上短按两次 BOOT**（安全→预警→危险），
观察所有其它节点屏幕从 `SAFE` → `WARN` → `DANGER`(反白闪烁)。

## 两板最小闭环 Demo（对应 DoD①②）

准备：板A烧 `NODE_ROLE=1`(Node_A)，板B烧 `NODE_ROLE=2`(Node_B, 中继)。
两块板都不连 WiFi、上电放一起，各接 115200 串口。

1. 上电：两块屏都显示 `SAFE`；板B 顶部 `M1`（看到 A 的心跳，在线）。板A 同理看到 B。
2. **短按板A BOOT** → 屏变 `WARN`（预警：强降雨，向高处）；板B 约 1 帧内变为 `WARN`，顶部出现 `RX`。
3. **再短按板A BOOT** → 屏变 `DANGER` 并**整屏反白闪烁**，显示逃生方向导航（下一跳 `SHELTER` + 方向 + 剩余距离）；
   板B 同步进入紧急闪烁界面。板A 若再按一次回到 `SAFE`，板B 约 4s 内回到 `SAFE`。
4. 长按板A（≥0.8s）：立即重发当前状态，可用于演示“主动上报”。

串口侧可见：板A 每次短按打印 `[SIM] scenario=…`；发送方打印可选 `[TX]`（默认注释）；
接收方把 `printInfo()` 或 `[RX]` 打开即可看到邻居表更新。

## 现场演示清单

- [ ] 两块板角色已烧录（A/B），NODE_ID 唯一
- [ ] 屏幕均显示 `SAFE`，且顶部能看到邻居 `M1`（组网成功）
- [ ] 短按 A：B 屏幕同步 `WARN`
- [ ] 再短按 A：B 同步 `DANGER` 反白闪烁，并显示撤离文案/箭头
- [ ] 长按 A：立即广播重发（演示主动上报）
- [ ] 关闭某一块，其它屏对应邻居数下降（体现“在线状态”）

## 现场可调小参数速查
- 想更“快”：`renderUi()` 帧间隔 `80`→`40` ms。
- 想更“醒目”：反白频率 `350`ms 调小；外接告警灯设 `ALARM_PIN`。
- 距离更远：给中继板烧角色 2，并把 `MAX_HOPS` 调大（注意广播风暴）。


## 水位输入单节点实测

[WaterSensorNode](../firmware/WaterSensorNode/README.md) 提供 GPIO5 真实采样到 OLED 的独立演示，
包括每秒日志、干湿标定与进度条。已验证 1cm 浸水有明确响应，3cm 满量程仍需按指南重新采集。
这项结果不表示水位已经通过 ESP-NOW 发送到 App；原有多节点通信演示仍使用上文 AIxNode 固件。
